Présentation

Le jeu 2D est terminé. Le module bonus s’attaque à la troisième dimension avec Pyxel Cube, le moteur 3D livré avec Pyxel depuis la version 3.0.

Ce premier chapitre tient en une promesse : à la fin, une fenêtre affiche un sol et un cube qui tourne. Rien de plus, et c’est volontaire. Le cube est le programme le plus court qui montre les quatre pièces d’une scène 3D : un nœud, une transformation, une caméra, un dessin.

La différence de méthode avec le parcours 2D est nette. En 2D, vous écriviez un Game qui appelait pyxel.blt(), et vous calculiez vous-même le décalage de la caméra. En 3D, Pyxel Cube impose sa structure : un arbre de nœuds, chacun capable de se mettre à jour et de se dessiner, et une caméra qui projette l’ensemble. Vous ne réécrivez pas cette mécanique, vous l’utilisez.

Vérifier la version avant de commencer

Le module pyxel.cube n’existe pas dans Pyxel 2. Si from pyxel.cube import Camera provoque une erreur ModuleNotFoundError, c’est que la version installée est trop ancienne. Tout le module bonus suppose Pyxel 3.0.1.

Objectifs

À la fin du chapitre, vous devez pouvoir :

  1. importer les classes de pyxel.cube et savoir à quoi elles servent ;
  2. écrire une scène sous forme de sous-classe de Node ;
  3. placer une caméra avec Mat4.look_at() ;
  4. dessiner une boîte colorée avec box() ;
  5. situer un objet avec ses trois coordonnées x, y et z ;
  6. faire tourner un objet autour d’un axe ;
  7. relier la scène à la fenêtre par pyxel.run().

Le repère de Pyxel Cube

Avant d’écrire une ligne, il faut savoir où sont les axes, sinon les objets se placent au hasard. Pyxel Cube utilise un repère droitier, avec trois axes :

AxeDirectionExemple dans le chapitre
xvers la droitele cube est à x = 0, au centre
yvers le hautle sol est à y = 0, le cube au-dessus
zvers vous, hors de l’écranla caméra est à z = 140, devant la scène

La caméra regarde vers les z négatifs : c’est la constante Vec3.FORWARD, qui vaut (0, 0, -1). Une caméra placée à z = 140 voit donc la scène qui se trouve plus près de zéro, exactement comme dans le chapitre.

Les unités sont libres. Pyxel Cube ne connaît ni tuile ni pixel : une longueur de 32 vaut 32 unités de monde, et c’est la caméra qui décide de la taille à l’écran. Le chapitre garde des nombres proches des pixels 2D, avec un sol de 200 unités de côté, pour que les ordres de grandeur restent familiers.

Le sol sert de repère

Un objet seul dans le vide ne montre pas où est le haut. Le sol du chapitre n’est pas décoratif : il rend le sens de y évident, et il rend visible la moitié des erreurs de placement.

Le code complet

import pyxel
from pyxel.cube import Camera, Mat4, Node, Shading, Vec3


SCREEN_WIDTH = 256
SCREEN_HEIGHT = 256
BACKGROUND_COLOR = pyxel.COLOR_BLACK

GROUND_SIZE = 200.0
GROUND_COLOR = pyxel.COLOR_GREEN

CUBE_SIZE = 32.0
CUBE_COLOR = pyxel.COLOR_CYAN
CUBE_HEIGHT = 16.0
CUBE_SPEED = 1.0

CAMERA_HEIGHT = 60.0
CAMERA_DISTANCE = 140.0


class Ground(Node):
    def on_draw(self):
        self.box(
            Mat4.from_translation(Vec3(0.0, -1.0, 0.0)),
            Vec3(GROUND_SIZE, 2.0, GROUND_SIZE),
            GROUND_COLOR,
        )


class Cube(Node):
    def on_update(self):
        spin = Mat4.from_euler(
            Vec3(0.0, pyxel.frame_count * CUBE_SPEED, 0.0),
        )
        self.transform = (
            Mat4.from_translation(Vec3(0.0, CUBE_HEIGHT, 0.0)) * spin
        )

    def on_draw(self):
        self.box(
            Mat4.IDENTITY,
            Vec3(CUBE_SIZE, CUBE_SIZE, CUBE_SIZE),
            CUBE_COLOR,
        )


class Scene(Node):
    def __init__(self):
        super().__init__()

        self.shading = Shading(pyxel.colors)

        self.camera = Camera()
        self.camera.clear_color = BACKGROUND_COLOR
        self.camera.transform = Mat4.look_at(
            Vec3(0.0, CAMERA_HEIGHT, CAMERA_DISTANCE),
            Vec3(0.0, CUBE_HEIGHT, 0.0),
        )

        self.add_child(Ground())
        self.add_child(Cube())


class App:
    def __init__(self):
        pyxel.init(
            SCREEN_WIDTH,
            SCREEN_HEIGHT,
            title="Cube 1 - scene 3D",
        )

        self.scene = Scene()

        pyxel.run(self.update, self.draw)

    def update(self):
        if pyxel.btnp(pyxel.KEY_Q):
            pyxel.quit()

        self.scene.update()

    def draw(self):
        self.scene.draw(0, 0, pyxel.width, pyxel.height)

Comprendre le programme

Trois lignes d’import

Le programme importe pyxel comme d’habitude, puis les cinq classes utiles du module 3D :

  • Node : un nœud de l’arbre de scène, avec ses enfants ;
  • Camera : le point de vue qui projette la scène ;
  • Vec3 : un vecteur à trois coordonnées, utilisé pour les positions et les tailles ;
  • Mat4 : une matrice de transformation, utilisée pour placer et orienter ;
  • Shading : la table de luminosité qui donne du relief aux faces.

Le reste du fichier ne contient que des constantes, quatre classes et deux appels à Pyxel.

Un sol et un cube, deux nœuds

Ground et Cube héritent de Node et redéfinissent une seule méthode : on_draw(). C’est le point qui change tout par rapport au parcours 2D. Personne n’appelle on_draw() dans le code : c’est draw() sur la scène qui parcourt l’arbre et appelle chaque nœud.

À l’intérieur, un seul appel :

self.box(Mat4.IDENTITY, Vec3(CUBE_SIZE, CUBE_SIZE, CUBE_SIZE), CUBE_COLOR)

box() dessine une boîte pleine. Le premier argument est un placement, le deuxième les trois longueurs d’arête, le troisième une couleur de la palette. Mat4.IDENTITY signifie « aucune transformation supplémentaire » : la boîte est dessinée exactement là où le nœud se trouve. Le placement est relatif au nœud, pas au monde, ce qui permet de dessiner une forme simple et de déplacer le nœud librement.

Le sol mesure 200 unités de côté et 2 d’épaisseur. Il est placé à y = -1, donc sa face supérieure tombe exactement sur y = 0. Le cube mesure 32 unités et son centre est à y = 16 : sa face inférieure touche elle aussi y = 0. Ces deux calculs expliquent pourquoi le cube paraît posé sur le sol et non enfoncé dedans.

La scène porte la caméra

Scene est la racine de l’arbre. Son constructeur fait quatre choses, dans cet ordre.

  1. self.shading = Shading(pyxel.colors) construit une table de luminosité à partir de la palette : pour chaque couleur, huit niveaux, du plus sombre au plus clair. Une lumière par défaut éclaire la scène ; sans elle, toutes les faces auraient la même teinte et le cube ressemblerait à un carré.
  2. self.camera = Camera() crée le point de vue. La caméra est posée sur la scène, pas sur un objet : draw() l’utilise pour tout le sous-arbre.
  3. self.camera.clear_color = BACKGROUND_COLOR demande à remplir la zone de dessin avec du noir avant de projeter la scène.
  4. self.camera.transform = Mat4.look_at(...) oriente la caméra. Le premier vecteur est la position de l’œil, le second le point visé. Le troisième argument, l’axe vertical, est facultatif et vaut Vec3.UP par défaut.

La caméra se trouve à (0, 60, 140) et vise (0, 16, 0), le centre du cube. Elle est donc un peu plus haut que le cube et à 140 unités devant lui. Les réglages par défaut de Camera suffisent : champ de vision vertical de 60 degrés, plan proche à 0,1 et plan lointain à 1000. Seuls les objets situés entre ces deux distances sont dessinés.

Pourquoi doubler la mise à jour et le dessin

Chaque nœud a deux méthodes vides, on_update() et on_draw(). Vous ne redéfinissez que celles dont vous avez besoin : le sol ne bouge pas, il n’a donc que on_draw() ; le cube a les deux.

Une rotation calculée à chaque image

La mise à jour du cube tient en trois lignes :

spin = Mat4.from_euler(Vec3(0.0, pyxel.frame_count * CUBE_SPEED, 0.0))
self.transform = Mat4.from_translation(Vec3(0.0, CUBE_HEIGHT, 0.0)) * spin

Mat4.from_euler() construit une rotation à partir de trois angles exprimés en degrés, appliqués autour des axes x, puis y, puis z. Ici, seul l’angle y varie : le cube tourne sur lui-même comme une toupie. Avec CUBE_SPEED = 1.0 et 30 images par seconde, l’angle augmente de 30 degrés par seconde, soit un tour complet en douze secondes.

La multiplication de matrices se lit de gauche à droite dans l’ordre des opérations : d’abord la rotation, puis la translation. Le cube tourne donc sur lui-même, puis se place à la hauteur voulue. Inverser les deux termes ferait tourner le cube autour du centre du monde, et il décrirait un cercle au lieu de rester sur place.

La position est recalculée entièrement à chaque image à partir de pyxel.frame_count, jamais ajoutée à la valeur précédente. C’est volontaire : une addition répétée finit par accumuler les erreurs d’arrondi, alors qu’un calcul absolu ne dérive pas, même après plusieurs heures.

App : la fenêtre et la boucle

La classe App ne fait que relier la scène à Pyxel. pyxel.init() ouvre une fenêtre de 256 sur 256 avec un titre, puis pyxel.run(self.update, self.draw) prend la main : Pyxel appelle ces deux méthodes à chaque image, trente fois par seconde.

update() traite la touche Q, puis appelle self.scene.update() : la scène parcourt son arbre et exécute les on_update(). draw() appelle self.scene.draw(0, 0, pyxel.width, pyxel.height) : la scène parcourt à nouveau son arbre, mais cette fois pour dessiner, avec la caméra trouvée sur la racine.

Une seule ligne relie les deux mondes, celle de draw(). Tout ce qui suit dans le parcours bonus se contente d’enrichir l’arbre : des nœuds en plus, des transformations en plus, un peu de logique.

Vérifier le résultat

Lancez le programme et contrôlez ces cinq points.

  1. La fenêtre s’intitule « Cube 1 - scene 3D » et mesure 256 sur 256 pixels.
  2. Un sol plat occupe le bas de l’écran, vu de dessus et de face à la fois.
  3. Un cube coloré posé sur le sol tourne régulièrement autour de son axe vertical, sans à-coup ni tremblement.
  4. Les faces du cube n’ont pas toutes la même teinte : le relief est visible.
  5. La touche Q ferme la fenêtre proprement.

Si le cube tourne mais que le sol tremble, la rotation est appliquée à la scène au lieu du cube. Si l’image est parfaitement figée, self.scene.update() a été oublié dans update().

Les trois appels à ne pas oublier

Une scène 3D silencieuse vient presque toujours de l’un de ces trois appels manquants : la caméra dans le constructeur, update() dans la mise à jour, draw() dans le dessin. Avant de chercher ailleurs, vérifiez les trois.

Une constante par réglage

Déplacer une valeur dans une constante nommée coûte une ligne et évite de fouiller le fichier. C’est la même discipline que dans le parcours 2D, et elle devient plus utile encore en 3D, où les nombres sont moins parlants.

À retenir

  • Pyxel Cube s’importe depuis pyxel.cube et demande Pyxel 3.0 ou plus.
  • Une scène est un nœud : ses enfants sont les objets, la caméra et la lumière sont sur la racine.
  • on_update() et on_draw() sont appelées par update() et draw() de la racine, jamais directement.
  • Mat4.look_at() place la caméra, Mat4.from_translation() et Mat4.from_euler() placent et orientent un objet.
  • Un objet posé sur un sol de hauteur y = 0 a son centre à la moitié de sa hauteur.
  • L’ordre translation puis rotation garde un objet sur place ; l’ordre inverse le fait tourner autour du monde.
  • Trois appels font vivre la scène : la caméra, scene.update(), scene.draw().

Le chapitre suivant en fait une scène peuplée : un objet parent qui entraîne ses enfants, des transformations qui s’additionnent, et une caméra que le clavier fait tourner.
