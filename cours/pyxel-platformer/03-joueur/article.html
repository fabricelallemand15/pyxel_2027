Présentation

Dans les deux premières leçons, le joueur se déplaçait seul et rebondissait sur les bords de l’écran. Le programme ne lisait aucune touche, sauf pour quitter.

Cette leçon confie le déplacement au clavier. Les flèches gauche et droite déplacent le joueur, qui reste à l’intérieur de la fenêtre.

La structure ne change pas : Game coordonne le jeu, Level dessine le décor, Player gère le personnage. Seul le comportement du joueur est modifié.

Objectifs

À la fin de la leçon, vous devez pouvoir :

  1. lire l’état d’une touche avec pyxel.btn() ;
  2. distinguer btn() et btnp() ;
  3. calculer un déplacement à partir des touches pressées ;
  4. limiter une position avec pyxel.clamp() ;
  5. modifier le comportement d’une classe sans changer son interface.

Ce qui change

Trois éléments de la leçon 2 disparaissent ou sont remplacés :

  • le déplacement automatique et son rebond sur les bords ;
  • la détection du changement de direction et le bruitage associé ;
  • la constante PLAYER_SPEED, qui passe de 1 à 2.

Le décor reste décoratif

Les plateformes et les pièces sont toujours dessinées par la tilemap, mais le joueur les traverse : aucune collision n’est encore calculée.

Le joueur peut donc marcher devant une plateforme sans être arrêté. Les collisions seront étudiées dans une leçon ultérieure.

Le code complet

Le projet contient toujours deux fichiers : main.py et res.pyxres, dans le même dossier.

import pyxel


SCREEN_WIDTH = 256
SCREEN_HEIGHT = 256
RESOURCE_FILE = "res.pyxres"

TILE_SIZE = 8
LEVEL_WIDTH = 32
LEVEL_HEIGHT = 32

PLAYER_WIDTH = 8
PLAYER_HEIGHT = 8
PLAYER_SPEED = 2
PLAYER_TILE_X = 0
PLAYER_TILE_Y = 0
PLAYER_START_X = 40
PLAYER_START_Y = 216

BACKGROUND_COLOR = pyxel.COLOR_DARK_BLUE
TEXT_COLOR = pyxel.COLOR_WHITE
TRANSPARENT_COLOR = 0

MUSIC = 0


class Level:
    def __init__(self):
        self.width = LEVEL_WIDTH * TILE_SIZE
        self.height = LEVEL_HEIGHT * TILE_SIZE

    def draw(self):
        pyxel.bltm(
            0,
            0,
            0,
            0,
            0,
            self.width,
            self.height,
        )


class Player:
    def __init__(self, x, y):
        self.x = x
        self.y = y
        self.width = PLAYER_WIDTH
        self.height = PLAYER_HEIGHT
        self.dx = 0

    def update(self):
        self.dx = 0

        if pyxel.btn(pyxel.KEY_LEFT):
            self.dx = -PLAYER_SPEED
        elif pyxel.btn(pyxel.KEY_RIGHT):
            self.dx = PLAYER_SPEED

        self.x += self.dx
        self.x = pyxel.clamp(
            self.x,
            0,
            pyxel.width - self.width,
        )

    def draw(self):
        pyxel.blt(
            self.x,
            self.y,
            0,
            PLAYER_TILE_X * TILE_SIZE,
            PLAYER_TILE_Y * TILE_SIZE,
            self.width,
            self.height,
            TRANSPARENT_COLOR,
        )


class Game:
    def __init__(self):
        pyxel.init(
            SCREEN_WIDTH,
            SCREEN_HEIGHT,
            title="Chapitre 3 - joueur",
        )
        pyxel.load(RESOURCE_FILE)

        self.level = Level()
        self.player = Player(
            PLAYER_START_X,
            PLAYER_START_Y,
        )

        pyxel.playm(MUSIC, loop=True)
        pyxel.run(self.update, self.draw)

    def update(self):
        if pyxel.btnp(pyxel.KEY_Q):
            pyxel.quit()

        self.player.update()

    def draw(self):
        pyxel.cls(BACKGROUND_COLOR)
        self.level.draw()

        pyxel.text(
            4,
            4,
            "Chapitre 3 - joueur",
            TEXT_COLOR,
        )
        pyxel.text(
            4,
            12,
            "Gauche et droite : marcher",
            TEXT_COLOR,
        )

        self.player.draw()


Game()

Le résultat attendu :

  • une fenêtre de 256 × 256 pixels ;
  • le niveau de la leçon 2 ;
  • un joueur immobile au départ ;
  • un déplacement vers la gauche ou la droite avec les flèches ;
  • un joueur qui ne sort jamais de l’écran ;
  • la touche Q qui ferme l’application.

Comprendre le programme

Lire le clavier avec btn()

if pyxel.btn(pyxel.KEY_LEFT):
    self.dx = -PLAYER_SPEED
elif pyxel.btn(pyxel.KEY_RIGHT):
    self.dx = PLAYER_SPEED

pyxel.btn() renvoie vrai tant que la touche est maintenue. La condition est donc vérifiée à chaque image : le joueur avance de façon continue.

Le mot-clé elif signifie que la seconde condition n’est examinée que si la première est fausse. Si les deux flèches sont pressées en même temps, la flèche gauche l’emporte.

btn() et btnp()

pyxel.btnp() renvoie vrai seulement à l’image où la touche est enfoncée. Il convient aux actions ponctuelles, comme quitter le jeu avec Q ou sauter.

pyxel.btn() renvoie vrai pendant toute la durée de l’appui. Il convient aux déplacements continus.

Utiliser btnp() pour un déplacement donnerait un joueur qui avance d’un seul pas par appui.

Remettre le déplacement à zéro

def update(self):
    self.dx = 0

    if pyxel.btn(pyxel.KEY_LEFT):
        self.dx = -PLAYER_SPEED
    elif pyxel.btn(pyxel.KEY_RIGHT):
        self.dx = PLAYER_SPEED

La première ligne remet dx à zéro à chaque image.

Cette remise à zéro est indispensable. Sans elle, le dernier déplacement enregistré resterait actif et le joueur continuerait d’avancer après le relâchement des touches.

Calculer la nouvelle position

self.x += self.dx

La position est mise à jour à partir du déplacement calculé.

Avec PLAYER_SPEED = 2, le joueur avance de 2 pixels par image vers la droite et recule de 2 pixels vers la gauche. Le signe de dx porte donc le sens du déplacement.

Rester dans l’écran

self.x = pyxel.clamp(
    self.x,
    0,
    pyxel.width - self.width,
)

pyxel.clamp() ramène une valeur dans un intervalle. Ici :

  • la valeur minimale est 0, le bord gauche de l’écran ;
  • la valeur maximale est pyxel.width - self.width, la position pour laquelle le bord droit du joueur touche le bord droit de l’écran.

Cette méthode remplace la série de tests de la leçon 2. Elle décrit la même règle en une seule opération : la position reste comprise entre deux bornes.

Une règle, un endroit

La limite de l’écran est décrite à un seul endroit du programme. Si la largeur de la fenêtre change, ou si le joueur change de taille, le calcul reste correct sans autre modification.

Où lire le clavier

Le clavier est lu dans Player.update(). La classe Game se contente d’appeler cette méthode :

def update(self):
    if pyxel.btnp(pyxel.KEY_Q):
        pyxel.quit()

    self.player.update()

Cette répartition convient à un petit jeu : le joueur connaît ses règles de déplacement, le jeu coordonne les éléments.

Une alternative possible

Un programme plus grand séparerait la lecture du clavier et le déplacement : Game lirait les touches, puis transmettrait une direction au joueur.

Cette séparation n’est pas nécessaire ici, et elle ajouterait des paramètres à toutes les méthodes. La forme actuelle sera conservée jusqu’à la fin de la formation.

Dessiner le joueur

La méthode Player.draw() ne change pas. Elle utilise toujours pyxel.blt() avec la tuile (0, 0) de la banque d’images.

Le dessin ne dépend que de la position courante. C’est la raison pour laquelle update() peut être réécrite sans toucher à draw().

Les accents à l’écran

Le texte « Gauche et droite : marcher » évite le mot « flèches » : la police de Pyxel ne dessine pas le è (voir la leçon 1).

Erreurs fréquentes

Le joueur avance d’un seul pas par appui

btnp() a été utilisé à la place de btn(). Pour un déplacement continu, il faut lire l’état de la touche à chaque image :

if pyxel.btn(pyxel.KEY_RIGHT):

Le joueur continue après le relâchement

La remise à zéro de dx a été oubliée au début de update() :

self.dx = 0

Cette ligne doit précéder la lecture des touches.

Le joueur sort de l’écran

L’appel à pyxel.clamp() est absent ou placé avant la mise à jour de la position. L’ordre correct est :

  1. calculer dx ;
  2. ajouter dx à x ;
  3. limiter x.

Rien ne se passe ou une erreur de nom apparaît

Vérifiez l’orthographe des constantes de touches : pyxel.KEY_LEFT et pyxel.KEY_RIGHT. Elles sont en majuscules.

Expérimentations

Ces modifications sont facultatives.

Changer la vitesse

PLAYER_SPEED = 4

Le déplacement devient plus rapide. Une valeur trop grande donne l’impression de sauts d’un bord à l’autre de l’écran ; une valeur de 1 rend le joueur très lent.

Ajouter les touches A et D

if pyxel.btn(pyxel.KEY_LEFT) or pyxel.btn(pyxel.KEY_A):
    self.dx = -PLAYER_SPEED
elif pyxel.btn(pyxel.KEY_RIGHT) or pyxel.btn(pyxel.KEY_D):
    self.dx = PLAYER_SPEED

Le mot-clé or rend la condition vraie si l’une des deux touches est pressée.

Changer la position de départ

PLAYER_START_X = 120

Le joueur apparaît au milieu de l’écran. La position verticale doit rester cohérente avec le haut du sol, à la coordonnée 224.

Observer l’effet de clamp()

Retirez temporairement l’appel à pyxel.clamp(), puis déplacez le joueur jusqu’au bord de l’écran. Le sprite disparaît : sa position continue d’augmenter alors qu’il n’est plus visible. Remettez ensuite l’appel en place.

À retenir

  • pyxel.btn() renvoie vrai tant qu’une touche est maintenue.
  • pyxel.btnp() renvoie vrai seulement à l’image de l’appui.
  • dx porte le déplacement horizontal et son signe porte le sens.
  • La remise à zéro de dx rend le joueur immobile au relâchement.
  • pyxel.clamp() limite une valeur entre deux bornes.
  • La position est mise à jour dans update(), le dessin reste dans draw().
  • Le décor n’arrête pas encore le joueur : les collisions viendront plus tard.
